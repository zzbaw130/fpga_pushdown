# TPC-H SF=16: bounded-path correctness and cold-HOST model comparison

Date: 2026-10-14. This report compares a native PostgreSQL HOST run with a
parameterized CEMU CSD run. The ratio is a **cross-platform projection**, not
a measured FPGA/CSD hardware speedup.

## Configuration and evidence

- Dataset: `tpch_s16`, 95,988,640 `lineitem` rows; native PGDATA is
  `/data/dengyao/pgdata/tpch_s16`. Both PostgreSQL binaries were compiled from
  this repository's PG12 source, separately on the native host and in the
  CEMU guest. Guest PGDATA was already staged on the CEMU NVM namespace;
  9P/staging time is excluded.
- CEMU: original pure-memory 48 GiB NVM backend, 4 GiB FDMFS, 16 GiB guest RAM,
  TCG plus VM-Freeze (no KVM). The compute model used 250 MHz FPGA clock,
  1,000 MiB/s Flash read and write bandwidth, 32 parallel workers,
  `csd.program_runtime=0`, `csd.cache_fill=off`, 13,312 MiB query-local Flash
  spill, and a 3,600,000 ms host ioctl watchdog. The watchdog and functional
  C++ VM-Freeze wall time are not device latency.
- CSD kernel: `csd_sql_sf16_bounded_v4.so`, SHA-256
  `888aa13914807f48d59d62d4f74cc1e9b85207314668542d92724571b33e1e24`.
  Raw CSD output, normalized answers and per-plan profiles are in
  `results/tpch_sf16_bounded_full_v4_final/`.
- Native HOST: the same SF=16 cluster on physical NVMe, `shared_buffers=1GB`,
  `autovacuum=off`, on an 80-logical-CPU Intel Xeon E7-4820 v3 (1.90 GHz)
  server with 109 GiB RAM. The CEMU container remained resident but had no
  active CSD query during the final HOST round. Every query restarted
  PostgreSQL, then `sync` and `vmtouch -e` were applied only to that cluster's
  `base/` files. The page
  residency immediately before each query was saved; the maximum was
  0.000778% (256 KiB of 31 GiB). Q15's temporary view was cleaned up. The
  no-concurrent-CSD-query round is in
  `results/tpch_sf16_native_host_cold_isolated_v2/`; the exploratory round is
  in `results/tpch_sf16_native_host_cold_v1/`.
- The per-query comparison, including both clocks and memory counters, is
  `results/tpch_sf16_bounded_vs_native_cold.csv`, generated by
  `scripts/summarize_sf16_dual_clock.py`. It rejects mismatched answers,
  missing profiles, spill allocation failures and warm HOST cache samples.

The raw directories and paired guest Q6 diagnostic are preserved in the
deterministic archive `results/tpch_sf16_bounded_cold_raw.tar.gz` (SHA-256
`dbf484d1055fc6b77b951ef6c642b8c077fb1ccbf97fea408695b9ddb50c69cb`).
It expands under `results/` to the paths named above. The pre-existing HOST
goldens can be restored from `results/tpch_sf16_validation_raw.tar.gz`.

The CSD functional run partly overlapped the *exploratory* native HOST round;
the final native HOST round did not overlap an active CSD query. Three
independent targeted CSD measurements of Q17/Q18/Q20 differed from the full
run's guest times by less than 1%, but the guest clock still contains
TCG-emulated PostgreSQL control overhead. Native CPU and device-side modeled
FPGA/Flash are different platforms; no physical FPGA speedup is claimed.

## Correctness and memory

Forced CSD Q1--Q22 all matched HOST output byte-for-byte. All 25 CSD
subplans reported `spill_failed_required_bytes=0`. Maximum spill high-water
was Q21's 9,137,763,384 B, below the 13,958,643,712 B capacity. Maximum
operator-arena peak was 580,811,129 B. The largest conservatively counted
ordinary C++ `Batch` was Q22's 3,230,706,240 B. The maximum per-plan sum of
non-operator FDM reservation, operator peak and `Batch` peak was
3,705,643,948 B. This sum does **not** include every STL allocation or
transient copy; the functional model still lacks an arena-backed allocator,
so it is not a proof of a strict physical 4 GiB controller-memory bound.

The direct Scan/FIFO-to-Flash grouped Aggregate path and its tiled HAVING/
Project consumer removed the largest old materializations; an oversized
right/build Scan can also stream into a Join with a non-Scan probe subtree.

| Query | Old Batch peak (B) | New Batch peak (B) | Old CSD guest ms | New CSD guest ms |
| --- | ---: | ---: | ---: | ---: |
| Q17 | 22,194,284,144 | 714,716,656 | 51,930.071 | 52,022.582 |
| Q18 | 15,550,897,984 | 571,052,512 | 43,996.877 | 54,958.980 |
| Q20 | 7,852,313,760 | 2,844,175,384 | 21,615.383 | 23,401.781 |

Extra Flash partition/replay raises the complete CSD model-path total from
the previous 850,480.919 ms to 863,532.928 ms (+1.53%). The trade-off is
lower tracked resident materialization; it does not yet eliminate all
ordinary STL allocations.

## Latency comparison

| Metric | Value |
| --- | ---: |
| CSD modeled-path Q1--Q22 total | 863,532.928 ms |
| Native cold-HOST Q1--Q22 total | 1,039,543.923 ms |
| Projected total-time ratio, HOST/CSD | 1.2038x |
| Per-query geometric-mean ratio | 1.1372x |
| Queries with CSD faster | 12/22 |
| Offline per-query minimum-path upper bound | 1.5513x |

The last row is an offline oracle, **not** the measured `csd.exe_path=auto`
planner. Ten queries (Q2, Q5, Q8, Q9, Q11, Q13, Q16, Q19, Q21 and Q22) were
faster on native cold HOST under these parameters. Q20 had the largest CSD
advantage (5.21x), while Q11 had the largest disadvantage (0.27x). Q9 and
Q22 are near ties and should not be treated as robust placement decisions
from one sample.

The exploratory HOST round totaled 1,032,132.986 ms, versus 1,039,543.923 ms
in the isolated, `autovacuum=off` final round. Query-level variance remains
(e.g. Q15: 44.50 s versus 55.85 s). Repeated samples and hardware-calibrated
Flash/FPGA parameters are needed before citing statistical speedup. Same-guest
TCG HOST is especially unsuitable: a paired Q6 diagnostic took 327.937 s
there, versus 31.479 s on native cold HOST; the corresponding CSD model path
was about 15 s. The roughly 21.6x same-guest Q6 ratio is therefore **not** a
native-HOST acceleration result.

## Reproduction

Run the CSD exact check inside the already staged CEMU guest:

```bash
cd /mnt/cemu
tar -xzf results/tpch_sf16_validation_raw.tar.gz -C .
./tests/test_csd_tpch_execution.sh --sf 16 --mode csd \
  --socket-dir /tmp/csdpg_nvme_tpch_s16 --port 57432 \
  --shared-library /workspace/code/CEMU/tests/cemu/build/csd_sql_sf16_bounded_v4.so \
  --host-golden-dir /mnt/cemu/results/tpch_sf16_host_golden \
  --output-dir /mnt/cemu/results/tpch_sf16_bounded_full_v4_final \
  --profile --cache-fill off --spill-mb 13312 \
  --execute-timeout-ms 3600000
```

Run the native cold-HOST baseline only after the active CSD run ends:

```bash
./tests/benchmark_native_host_tpch.sh --sf 16 --port 55448 \
  --output-dir results/tpch_sf16_native_host_cold_isolated_v2
python3 scripts/summarize_sf16_dual_clock.py \
  results/tpch_sf16_bounded_full_v4_final \
  results/tpch_sf16_native_host_cold_isolated_v2 \
  --output-csv results/tpch_sf16_bounded_vs_native_cold.csv
```
